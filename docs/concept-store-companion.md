# Концепція: «Супутник у залі»

> **Магазин спроєктований, щоб ти ходив довше. Цей агент — щоб ти пройшов один раз.**

Фінальна концепція проєкту, зафіксована 2026-08-09.
Замінює початкову ідею FoodQuest — див. [competitor-mashrum.md](competitor-mashrum.md).

## Проблема

**1. Магазин працює проти покупця — і це задокументовано.**
Галузевий стандарт планування торгового залу
([ABM Cloud](https://abmcloud.com/uk/planuvannya-torhovoho-zalu/)):

> «Логіка: **змусити покупця максимально довго перебувати в залі** для
> стимуляції незапланованих покупок»

Хліб, молоко, овочі свідомо ставлять «у дальньому кутку, щоб покупець пройшов
весь магазин». Це «золотий трикутник»: вхід → потрібне вглиб залу → каси
в протилежному боці.

**2. Застосунок перевантажений.** 18 пропозицій, попапи, яскраві картки,
переходи між екранами. Реальна поведінка: людина не читає нічого й діє навмання.
Доказ — гість активував 3 промо (Lion, круасани, соки Jaffa), яких **немає
в жодному з його чеків за 3 місяці**.

**3. 90% покупок — офлайн.** На тестовому акаунті онлайн-замовлень **нуль**,
усі 4 чеки — каса магазину. Але всі AI-рішення будуються під «вдома на дивані».

## Рішення

Один екран, який гість відкриває **вже в магазині**:

- Список зібрано агентом **заздалегідь і самостійно** (проактивність)
- Згруповано **за зонами в порядку обходу**, а не купою
- Викреслюєш на ходу, однією рукою
- Одна позиція «спробуй нове» — під раціон з чеків, не реклама

## Чотири складові

### 1. Спрощений інтерфейс
Нуль попапів, нуль каруселей. Список і чекбокси.

### 2. Маршрут по зонах
MCP **не дає** фізичного розташування товару в залі — перевірено, жоден
з 39 tools не має полів aisle/shelf/section.

Натомість: `get_categories_tree` дає категорію товару, а категорії корелюють
із зонами. Типова послідовність (лінійне планування, рух проти годинникової
стрілки — галузевий стандарт):

```
Вхід → овочі/фрукти → хліб/випічка → м'ясо/риба → молочка →
бакалія (центр) → заморозка → нехарчове → прикаса → каси
```

Периметр — свіже (там електрика для холодильників), центр — бакалія.

> **Чесне обмеження:** це **модель за галузевим стандартом**, а не планограма
> конкретного магазину. Планограми Сільпо — комерційна таємниця, плюс з 2018
> нові магазини роблять у тематичному дизайні (магазин-лабіринт у Києві),
> тобто планування різне. Видавати за точну навігацію не можна — треба
> називати як є.

**Схематична карта.** Маршрут малюється на сітці 4×4
([StoreMap.tsx](../apps/mobile/src/screens/StoreMap.tsx)): свіже по верхньому
периметру, бакалія в центрі, каси біля входу. Кожна зона має номер зупинки,
пройдені сіріють. Під картою — підпис, що це схема типового супермаркету,
а не план конкретного магазину.

Геометрія покрита тестами: зони не накладаються, не виходять за сітку,
не перекривають маркер входу, і сусідні зупинки маршруту не «телепортуються»
через увесь зал.

### 3. Проактивність (сценарій B3)
Агент не чекає запиту. Сам вирішує, коли зібрати список:

- позиція закінчується за ритмом чеків
- купон згорає завтра (`endDate`)
- звична позиція подорожчала (`catalogProduct.price` vs ціна чека)
- прийшли нові промо (тижневий цикл)

Це найсильніше по критерію «агентність»: агент вирішує **коли** діяти,
а не лише **що** робити.

### 4. Відкриття нового
Одна позиція під раціон з чеків. Не реклама — рекомендація.

## Ланцюжок tools (критерій агентності)

```
get_my_offline_orders        → ритм покупок, ціни в чеках
  ↓ код рахує подорожчання (catalogProduct.price)
get_my_coupons + get_coupon_details → що згорає, що підходить
  ↓ модель звіряє купони з раціоном (списку товарів немає — тільки текст)
get_my_shopping_cart + get_shopping_cart_by_id → контекст
find_products_batch          → резолв позицій
get_similar_products         → заміни для того, що подорожчало >20%
get_categories_tree          → категорія кожного товару → зона
  ↓ код будує маршрут
add_or_update_cart_products  → кошик (для тих, хто замовляє онлайн)
  ↓
Список за зонами + checkout-посилання
```

**10+ викликів, розгалуження, робота з контекстом.** Критерій 3 закрито.

## Чому це не «ще один асистент»

- **Момент інший.** Усі роблять «вдома на дивані». Ми — «в залі, руки зайняті».
- **Машрум цього не вміє.** Він чат; він не веде залом і не бачить історії цін.
- **Виростає з реальної злості автора**, а не з аналізу дір конкурента.
- Закриває критерій «реалістичність інтеграції» — це очевидна фіча для
  мобільного застосунку «Сільпо».

## Що лишається неперевіреним

- **Затримка появи офлайн-чеків** не виміряна. Для «що закінчується» не критично,
  для «щойно купив» — критично.
- **Порядок зон — евристика.** Треба або валідувати на реальних магазинах,
  або чесно позиціонувати як модель.
- **«Спробуй нове» ризикує стати рекламою** — має спиратись на раціон,
  інакше втрачає довіру.
